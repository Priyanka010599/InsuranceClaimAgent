# Insurance Claim Processing Agent

A LangGraph agent (Claude via `langchain-anthropic`) that ingests an insurance
claim, extracts structured data, validates it against policy documents (RAG),
assesses fraud/risk, routes to auto-approve / auto-deny / human escalation,
and notifies the claimant.

Portfolio project: synthetic data only, no real PII.

## Architecture

```
START -> intake -> extract -+-> validate -> policy_check -> assess_risk -> decide -+-> notify -> END
                             |                                                      |
                             +-------------------(extraction failed)----------------+
                                                                                     |
                                                                    (escalate) human_review -> notify
```

- **intake**: normalizes raw claim text, rejects oversized input (cost/abuse guard).
- **extract**: Claude + Pydantic structured output (`ClaimData`). On failure,
  routes straight to `notify` instead of crashing the pipeline.
- **validate**: internal consistency checks on the extracted data (e.g. positive
  amount, non-future incident date).
- **policy_check**: RAG. Retrieves relevant clauses from `policy_docs/` (local
  HuggingFace embeddings + in-memory vector store) and asks Claude whether the
  claim falls within policy terms.
- **assess_risk**: Claude scores fraud/risk 0-100 with flagged concerns. Sends
  only the fields relevant to risk scoring (PII minimization). Fails toward
  escalation, not silent approval, if the model's output can't be trusted.
- **decide**: routes validation errors to `auto_deny`; policy violations or
  risk_score >= 50 to `human_review`; otherwise to `auto_approve`.
- **human_review**: `interrupt()`-based human-in-the-loop; pauses and resumes
  via a checkpointer (`InMemorySaver`) once a human supplies a decision.
- **notify**: formats the outcome message to the claimant.

## Setup

```bash
python -m venv venv
source venv/Scripts/activate   # Windows Git Bash; use venv\Scripts\activate.bat for cmd
pip install -r requirements.txt
cp .env.example .env           # then fill in ANTHROPIC_API_KEY
```

## Run

```bash
python main.py                                    # inline sample claim
python main.py sample_claims/auto_claim_clean.pdf  # real PDF ingestion
python -m eval.run_eval                            # scores routing against 6 labeled cases
```

`sample_claims/` has 3 synthetic claim PDFs (clean auto, glass-damage-over-threshold,
home storm damage) generated by `generate_sample_pdfs.py`; `pdf_loader.py` extracts
text via `pypdf` before it reaches `intake`.

Optional: set `LANGSMITH_TRACING=true` and `LANGSMITH_API_KEY` in `.env` to trace
every run in LangSmith. No code changes needed, tracing activates automatically.

## Known limitations

- `ClaimData` is stored in checkpoints via msgpack; LangGraph currently warns
  that unregistered custom types will be blocked in a future version. Fine for
  a demo; would need explicit type registration for production use.
- Policy documents are two small synthetic markdown files, not real policy PDFs.
- `decide`'s thresholds (e.g. `risk_score >= 50`) are illustrative, not tuned
  against real claims data.

## Stack

Python 3.11+, LangGraph, langchain-anthropic, langchain-huggingface
(local embeddings, free), Pydantic.
